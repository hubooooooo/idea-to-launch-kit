# 文档模板：前端适配声明、前端阶段开发文档

文件默认放在项目的 `docs/` 下；项目已有文档约定时按项目约定。已经有前端阶段开发文档的，校验并补齐，不另写一套。

## 《前端适配声明》

正式编码前写，短、明确、可确认优先。

```markdown
# 前端适配声明

## 1. 项目判断
- 产品类型：
- 主要用户：
- 主要终端：桌面 Web / 移动 Web / 其他
- 新项目或已有项目：
- 本阶段业务目标：

## 2. 输入资料
- 需求文档：已读取 / 缺失
- 后端技术适配声明与决策记录：已读取 / 缺失
- 后端阶段留下的界面：无 / 临时验收界面（本阶段废弃）/ 纵向切片（在其上继续）
- 接口文档：完整 / 草案 / 缺失
- 设计稿：有 / 无
- 现有代码：有 / 无

## 3. 技术选择
- 框架与版本：
- 样式与组件策略：
- 数据请求与状态策略：
- 流式通信策略：
- 表单方案：
- 测试方案：
- 部署环境：

## 4. Agent 状态
- 后端状态 → 前端统一状态映射：
- 等待用户确认方式：
- 取消、重试、断线恢复方式：
- 任务 ID 和恢复入口：

## 5. 页面与产物
- 核心页面：
- 核心业务闭环：
- 产物类型和预览方式：
- 响应式目标：
- 前端子阶段规划：一行一个子阶段，写"编号 / 做什么 / 用户验收时做什么"；合并或省略的写明原因

## 6. 偏离本规范的地方
- 偏离项：
- 原因：
- 影响：

## 7. 待确认事项
- 影响前端且仍待定的决策，用决策卡格式（问题 / 选项 / 推荐 / 不选的后果），不超过 5 个；已定的不再问
```

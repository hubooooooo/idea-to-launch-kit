## 1. 统一任务状态模型

| 统一状态 | 用户看到什么 | 前端要做什么 |
| --- | --- | --- |
| `idle` | 尚未开始 | 显示输入和可执行条件 |
| `submitting` | 正在提交 | 禁止重复提交，允许取消请求 |
| `queued` | 已进入队列 | 显示任务已受理，不伪装成正在生成 |
| `running` | 正在执行 | 显示真实进度、阶段或活动提示 |
| `streaming` | 正在持续输出 | 增量展示，避免页面频繁跳动 |
| `waiting_user` | 等待用户确认或补充 | 明确需要用户做什么、为什么 |
| `succeeded` | 已完成 | 展示产物和下一步操作 |
| `partially_succeeded` | 部分成功 | 清楚区分成功项和失败项 |
| `failed` | 执行失败 | 说明发生了什么、能否重试 |
| `cancelled` | 已取消 | 保留已有信息，允许重新开始 |
| `disconnected` | 连接中断 | 说明任务未必停止，尝试恢复 |
| `stale` | 状态可能过期 | 主动重新获取后端真实状态 |

后端可以用不同名字，前端在适配层映射成统一含义。未知状态不静默当成成功或失败，记录下来并显示安全的兜底状态。

状态不是一个转圈图标。每个状态回答：现在发生了什么？我需要做什么？接下来会发生什么？

数据加载状态单独区分：

- `loading`：数据还没回来；
- `empty`：请求成功，但确实没有数据；
- `failed`：请求没有成功；
- `permission_denied`：无权查看；
- `not_found`：对象不存在或已删除。

接口还没返回时，不先显示"暂无模板""暂无任务"——这种瞬时错误信息会让用户以为系统里没数据。

## 2. 流式输出、轮询和断线恢复

### 选择顺序

| 场景 | 默认 |
| --- | --- |
| 服务端单向持续推送文本或进度 | SSE 或 Fetch Streaming |
| 双向高频通信 | WebSocket |
| 后端暂时只支持状态查询 | 有节制的轮询 |
| 只等一个普通短请求 | 普通 HTTP |

不要为了"实时感"强行用 WebSocket。

### SSE

- 原生 `EventSource` 适合 GET，但不方便设自定义请求头；需要 POST、请求体或特殊鉴权时用 Fetch Streaming。
- Cookie 鉴权优先走同源接口。
- 有些代理会缓冲响应，必须在真实部署链路上验证内容是逐段到达的。
- 页面卸载、切换任务和取消时关闭连接。
- 断线后先按任务 ID 查状态，再决定是否重连，不盲目重新创建任务。
- 后端 SSE 一定以 `done` 或 `error` 收尾。前端收到 `error` → `failed`，展示其中的 `message`；**连接关闭但没收到 `done` → `disconnected`**，按任务 ID 回查后端状态；不把没有 `done` 的关闭当成成功。

### 轮询

- 明确间隔和退避策略；页面不可见时降频或暂停；
- 完成、失败、取消后立即停；
- 不让每个组件各自轮询同一任务；
- 接口失败时不无限高频重试。

### 增量展示

- 流式文本批量刷新，不让每个字符触发复杂重渲染；
- 只在用户仍停留在底部时自动滚动；用户往上看历史时不强行拉回底部；
- 日志、思考过程和用户可见结果分层，不把内部敏感信息直接展示；
- 断线重连后去重，避免重复追加相同内容。

## 3. 语音与实时多媒体交互

核心交互是实时语音（语音对练、语音问答）时，链路是：

```text
麦克风录音 → 上传 → 后端 ASR 转写 → Agent 生成回复 → TTS 合成 → 音频流回传 → 前端播报
```

前端额外处理：

1. **麦克风授权**：浏览器只在 HTTPS 或 localhost 下开放麦克风。手机通过局域网地址（`http://192.168.x.x:3000`）访问时两者都不是，会被直接拒绝。授权被拒要给明确引导，不静默失败；未授权不开始录音。
2. **音频流播报**：音频分片和文本分片的事件名、编码以后端接口定义为准（例如 SSE 分别推送文本事件和 base64 音频分片事件，是并行的两条流）。用 Web Audio API 按时间轴排队播放，避免重叠；会话结束或切换时重置队列。
3. **iOS / Safari 兼容**：`MediaRecorder` 支持的容器格式不同——Chrome 是 `webm/opus`，iOS / Safari 是 `mp4/aac`。运行时探测 mime，并把实际格式随上传告诉后端。
4. **交互从简**：MVP 优先"回合制对讲机"（按下说话、再按发送）；全双工和打断留到后续。
5. **会后回放**：整段回放加逐句点播。Cookie 鉴权下同源 `<audio src>` 会自动带 Cookie，直接用；只有后端要求 Bearer 请求头时，才用 fetch 取 blob 生成 Object URL，用完 `revokeObjectURL`。

### 上线前的真机验收（本地 HTTPS）

- 不涉及麦克风、摄像头：手机和电脑连同一个 Wi-Fi，用局域网地址访问即可。
- 涉及麦克风、摄像头：`next dev --experimental-https` 的证书只覆盖 localhost。用 mkcert 为电脑的局域网 IP 签发证书，再用 `next dev -H 0.0.0.0 --experimental-https --experimental-https-key <key> --experimental-https-cert <cert>` 启动。然后让用户：
  1. 把 mkcert 的根证书 `rootCA.pem` 发到手机（隔空投送、微信文件或邮件）。**只发这一个，绝不发 `rootCA-key.pem`。**
  2. iPhone：打开文件，允许下载描述文件；"设置 → 已下载描述文件"里安装；再到"设置 → 通用 → 关于本机 → 证书信任设置"打开完全信任。
  3. Android："设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书"，选这个文件（菜单名因品牌略有差异）。
  4. 手机浏览器打开 `https://192.168.x.x:3000`，正常打开、地址栏没有"不安全"提示即成功。
  5. 验收结束后提醒用户在手机上删除这张证书。
- 做不到（手机装不了证书、设备受管控）：如实记为"待上线后验"，不写成已验证。

验收：真实手机（含 iPhone）走一遍录音 → 播报 → 回放；会中不出现无关信息；断网或离开页面后已完成的轮次仍保留。

## 4. 用户确认、防重复提交、取消和恢复

### 等待用户确认

界面要展示：已经完成了什么；为什么需要确认；可选项及各自影响；默认推荐项；确认后能否撤销；放弃或返回的方式。"继续""取消"之外，尽量用有业务意义的按钮，比如"采用这版分镜并生成视频"。

### 防重复提交

- 点击后立即进入明确的提交状态；完成前同一操作不可重复触发；
- 后端配合幂等键；
- 网络超时时，先查原任务是否已创建，再决定是否重试；
- 不允许多次点击产生多个昂贵的模型任务。

### 取消

前端"取消请求"和后端"取消任务"不是一回事：
- 取消浏览器请求：只是停止等待；
- 取消后端任务：需要后端提供真实取消能力；
- 后端不能取消时，按钮写"停止等待"或"离开页面"，不误导用户。

### 恢复

刷新、关闭或重新登录后：
1. 通过 URL 或任务列表找到任务 ID；
2. 向后端查询真实状态；
3. 恢复已有中间结果和产物；
4. 只在任务仍运行且协议允许时恢复流式连接；
5. 不重复创建同一个任务。

## 5. 产物展示

不要只为一种图片结果写死页面。统一产物模型：

```ts
type Artifact = {
  id: string;
  kind: "text" | "image" | "video" | "audio" | "file" | "json";
  name: string;
  status: "processing" | "ready" | "failed";
  url?: string;
  previewUrl?: string;
  mimeType?: string;
  size?: number;
  createdAt: string;
  metadata?: Record<string, unknown>;
};
```

项目可以扩展，但同一类产物的预览、下载、失败和加载方式要统一。

- 图片：占位、加载失败、放大查看、下载；
- 视频：封面、加载中、播放失败、基本控制；
- 音频：时长、播放状态、下载；
- 尺寸未知的媒体预留比例，避免页面跳动；
- 临时 Object URL 用完及时释放；
- 外链资源考虑过期、跨域和权限失败；
- 生成中的产物不伪装成最终完成。

结果与调试信息分层：默认界面先服务普通用户——结果、状态、下一步操作在前；请求 ID、原始 JSON、详细步骤和日志放进可折叠的"详情"或开发模式。不要把调试台直接当产品界面。

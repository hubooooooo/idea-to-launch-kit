## 1. 最低自动检查与脚本约定

每个可交付阶段至少执行：

```bash
npm run lint
npx tsc --noEmit      # 或项目里等价的 typecheck 脚本
npm test -- --run
npm run build
```

某项暂未配置时，补齐合理的最低配置并在阶段文档里说明，不直接写"跳过"。

脚本约定（方便任何检查脚本统一调用）：
- `package.json` 提供 `test`、`lint`、`build` 三个脚本；
- **Next.js 16 起已移除 `next lint`**，`next build` 也不再自动跑 ESLint。`lint` 脚本直接调用 `eslint .`；已有项目还写着 `next lint` 的，升级后要改；
- `test` 一次跑完就退出（Vitest 用 `vitest run`），不停在监听模式。

## 2. 测试分层

| 层级 | 重点 |
| --- | --- |
| 单元测试 | 状态映射、数据转换、校验、错误归一化 |
| 组件测试 | 表单、按钮状态、空 / 错 / 加载、确认交互 |
| 集成测试 | API 适配层与页面业务流程 |
| E2E | 一个真实用户从进入页面到获得结果的核心闭环（引入 Playwright 后；之前用可重复的"照着点"步骤代替） |
| 人工预览 | 视觉、文案、媒体、响应式、浏览器行为 |

## 3. 核心业务闭环

每个阶段至少有一条真正能操作的闭环：

```text
进入生成页 → 填写输入 → 成功提交 → 看到任务运行 → 处理用户确认（如有）
→ 看到最终产物 → 刷新页面后仍可恢复
```

只证明按钮能点、mock 数据能展示，不算业务闭环。

## 4. 浏览器检查

交付前真实启动前端和后端，用脚本化浏览器完成检查。默认写一个一次性的 Playwright 脚本（只当截图和检查工具用，不等于引入 E2E 套件），或用等价工具：

- 在 390、768、1280、1440 四个宽度打开核心流程的每个页面和弹窗并截图，截图存进项目的验收记录目录；
- 收集浏览器 Console 错误和失败的网络请求：交付时 Console 错误为零，失败请求逐条说明原因；
- 检查加载、空、错误、禁用和成功状态，以及侧栏、弹窗、下拉框和滚动；
- 走通真实后端接口和流式链路，检查图片、视频、音频和下载；
- 检查刷新、返回、断网后的恢复。

生产构建成功只能证明工程可构建，不能替代真实页面检查。

## 5. 交付判定与子阶段收尾

以下任一情况存在时不宣布完成：Lint 或类型检查有未解释错误；核心接口仍是 mock；核心页面在目标宽度不可用；失败状态丢失用户输入；重复点击创建多个任务；刷新后运行中的任务无法恢复；Console 持续报错；实现与确认的设计或需求明显不一致。

影响交付判定的问题不能带着交付，必须先解决。之外的已知问题（如某个非核心页面的视觉细节）列进阶段开发文档的"已知问题"，写明影响、临时处理和后续计划，由用户确认。

**关键业务规则还没冻结时**（评分公式、判定阈值、话术标准等）：不因此卡住开发——用临时规则跑通全链路，界面对用户显式标注"模拟 / 临时"；把规则做成可配置（JSON / 表），冻结后只改配置不改代码；在交付清单里列出仍待冻结的规则，不当作已完成。

**每个前端子阶段结束时**：
1. 真实启动前后端，按第 4 节完成浏览器检查；
2. 对接真实后端和真实模型，至少跑通一条核心闭环；没有真实 Key 时如实写"待验"，不拿 mock 冒充；
3. 本子阶段新增了要持久化的数据时，同步更新后端的重启恢复检查（见 agent-tech-stack 的验收参考）；
4. 跑第 1 节的四项检查和密钥扫描（确认前端代码、`.env.local` 以外的文件、构建产物里没有密钥）；
5. 更新 README 的启动与验证方法；
6. 给用户一份交付说明：预览地址和"照着点"步骤、桌面与移动端关键截图、各项检查的实际结果、未完成项和已知问题。

检查结果以命令的实际输出为准，不凭记忆填写；不因为构建成功就宣布页面完成，也不用 mock 代替最终联调。

给非技术用户的验收转述：打开预览地址，按"照着点"步骤从进入页面走到拿到一个真实结果；对照截图看手机和电脑上是否都能走完、第一次打开时有没有把"加载中"显示成"没有数据"、失败后知不知道怎么恢复、刷新后任务还在不在、重复点击会不会创建多个任务或重复扣费；发现异常就截图反馈。

## 6. 为上线做的准备

正式前端收尾前：`next.config` 设 `output: "standalone"`；准备 `frontend/Dockerfile`（多阶段构建、拷贝 `.next/static` 与 `public`、非 root 用户、`node server.js`、端口 3000）；后端地址按同源代理的做法在运行时读取。具体云平台的部署步骤不在本技能范围内。

## 7. 前端子阶段 0–4

不要按"先写完所有页面，再一次性接接口"拆阶段，按用户可验证的业务闭环拆。

**子阶段 0：适配与契约**（只产出文档）
- 读需求、后端技术适配声明、决策记录、后端接口定义和现有代码；判断后端阶段留下的界面是纵向切片、临时验收界面还是没有界面；
- 输出《前端适配声明》，写明上述判断和处理方式；
- 明确路由、页面清单、设计方向和接口契约；建立任务状态表和核心验收路径；标记尚未确认的假设。

**子阶段 1：可运行骨架**（已有纵向切片界面时与子阶段 2 合并；只有临时验收界面时在这里废弃并记录）
- 工程、布局、导航、设计变量和通用组件；
- 基础环境配置和 API 客户端；
- 一个代表页面；桌面和移动端基本布局正确；
- 配好 Lint、类型检查、测试和构建。

**子阶段 2：第一条真实闭环**
- 一个核心输入流程，对接真实创建任务接口；
- 展示队列、运行、成功和失败，以及至少一种真实产物；
- 写出可重复的"照着点"验收步骤；引入 Playwright 后补核心 E2E。

**子阶段 3：Agent 完整交互**
- 流式输出或轮询；等待用户确认；
- 取消、重试、断线和刷新恢复；
- 多任务、历史记录或任务中心（按需求）；
- 部分成功和未知状态。

**子阶段 4：质量与发布准备**
- 响应式、无障碍和多媒体检查；性能、错误监控和隐私；
- 与真实后端完整联调；清理 Console、Lint、类型和测试问题；
- 输出发布说明和已知问题。

具体项目可以合并子阶段，但每个子阶段都要有可运行、可查看、可验收的结果。已经验证过的纵向切片界面原地延续，不重复建设平行界面。

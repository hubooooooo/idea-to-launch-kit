## 1. 设计来源与视觉方向

优先级：
1. 已确认的设计系统和设计稿；
2. 需求中的品牌、用户和场景要求；
3. 已确认的参考产品（不直接复制其受保护资产）；
4. 第三方设计系统（用户给网址，你抓取其中的 DESIGN.md / token）；
5. 本技能的中性默认方案。

没有设计稿时，先输出简短视觉方向：颜色、字体、密度、圆角、页面结构和关键组件，再做首个代表页供确认，改到满意再铺开全站。

第三方设计系统只给了一个网址时，主动用命令行抓取解析，不让用户口述。SSR 页面一般能拿到完整 DESIGN.md；纯 SPA、需登录或有反爬的页面可能只拿到空壳，这时请用户把关键截图和 DESIGN.md 文本发过来，存进项目的设计参考目录。DESIGN.md 里的颜色、圆角、间距、阴影 token 可以直接落成 Tailwind `@theme`。开源 / 可商用的设计系统可以复用 token；受版权保护的只借鉴风格。

## 2. 样式落地：Tailwind + 语义变量

Tailwind 负责快速布局和原子样式，CSS 变量负责统一设计语言。颜色、圆角、阴影、间距尽量表达语义：

```css
@import "tailwindcss";

@theme {
  --color-bg: #ffffff;
  --color-surface: #f7f8fa;
  --color-text: #18202a;
  --color-muted: #667085;
  --color-primary: #5b5ce2;
  --color-danger: #d92d20;
  --radius-card: 16px;
}
```

Tailwind 4 起，`@theme` 里的变量会生成对应工具类（`bg-surface`、`rounded-card`）；`:root` 里的变量不生成工具类，只用于运行时切换的值（如深色主题覆盖）。还在 Tailwind 3 的已有项目沿用 `tailwind.config`。

不要让页面各处散落无法解释的颜色值，也不要把 Tailwind 本身当成完整设计系统。

## 3. 字体（中文产品必看）

- 设计系统自带的西文字体多不含中文字形，且部分是商业授权（如 Basier Circle），用前先确认授权；商业授权的不能直接打包。
- 落地用官方免费替代（Inter、Plus Jakarta Sans 等）+ 中文系统字体 fallback（PingFang SC / Microsoft YaHei / Noto Sans CJK SC）。
- `next/font` 加载的字体在构建时下载并自托管，运行时不请求外部 CDN；但 `next/font/google` 构建时要访问 Google，**国内网络下 `npm run build` 可能因此失败**。国内构建环境优先用 `next/font/local` 加载放进仓库的字体文件（先确认授权允许分发）。
- 保留"正文 + 展示标题"双字体思路，中文字形统一走系统字体。

## 4. 最低设计系统与组件策略

即使是 MVP 也至少统一：主色、背景、文本、边框和状态色；字号层级和行高；4 或 8 像素节奏的间距；圆角和阴影层级；按钮、输入框、卡片、弹窗、提示和标签；hover、focus、disabled、loading、error 状态；页面最大宽度和内容密度。

组件来源顺序：
1. 先复用项目已有组件；
2. 再用原生 HTML 和轻量自建组件；
3. 复杂交互用成熟的无障碍基础组件；
4. 确有必要才引入完整组件库。

组件库解决交互基础和开发效率，不替产品做视觉设计。

组件层级：基础组件（Button、Input、Select、Dialog）→ 复合组件（FileUploader、TaskStatus、ArtifactPreview）→ 业务组件（VideoGenerationForm、WorkflowRunPanel）→ 页面（组织布局和流程，不堆底层细节）。不为"复用"过早造出需要十几个参数的万能组件。

## 5. 图标和文案

- 统一图标库，不混用多套风格；不用表情符号替代正式功能图标；
- 只有图标的按钮要有可访问名称和悬停说明；
- 按钮文案写动作和结果（"生成分镜"），不只写"确定"；
- 状态文案用产品语言，不暴露内部技术术语；
- 每个页面只保留完成当前任务必需的文字，删掉装饰性标语、重复说明和次要标签；确认、费用、隐私、错误、空状态和上传限制的说明不算多余；
- 删掉装饰性文字后页面看不懂，说明布局有问题：先向用户提改布局的建议，确认后再改，不自行重做页面。

## 6. 响应式与移动端

默认验收宽度（需求另有规定除外）：390px（手机）、768px（平板 / 窄窗口）、1280px（常见桌面）、1440px（宽桌面）。

移动端规则：
- 桌面侧栏在手机上变成抽屉或底部导航；抽屉关闭时不残留透明遮挡层；
- 弹窗在小屏可滚动，主要操作始终可触达；
- 表格优先改成卡片、分组或受控横向滚动；
- 固定宽度媒体不撑破屏幕；触控目标建议不小于 44×44px；
- 键盘弹出时输入框和提交按钮不被完全遮挡；
- 页面不出现无意的横向滚动；
- 主题、侧栏等个性化设置保证 CSS、React 状态和持久化状态一致，不出现"按钮显示已收起，遮罩还挡着页面"。

响应式不能只看首页：核心流程的每个页面和弹窗都要查。

## 7. 无障碍基础

MVP 至少做到，并纳入浏览器检查：
- 核心操作可以用键盘完成，焦点位置清晰；弹窗有焦点约束，关闭后焦点回到触发处；
- 表单项有关联 Label，错误提示能被辅助技术识别并定位到字段；
- 只有图标的按钮有可访问名称；
- 状态不只靠颜色表达，文本与背景对比度足够；
- Agent 关键进度用适度的 live region，不让每个 Token 都被朗读。

## 8. 性能原则

先测量，再优化。MVP 至少做到：
- 首屏不加载当前页面用不到的大型库，富编辑器、图表、视频工具按需加载；
- 图片和媒体预留尺寸，减少布局跳动；
- 流式内容节流或批量更新，大列表分页；
- 相同接口不被多个组件重复请求，大型二进制不长期放在 React State。

不能用"以后优化"掩盖明显卡顿、内存泄漏和页面冻结。

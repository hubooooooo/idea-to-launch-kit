# 从本地 MVP 走向正式上线

目标只是本地可演示的 MVP 时，可以先不看这份。

开发阶段优先保持已验证的核心业务接口和数据契约稳定。SQLite、带 schema 版本的结构化文件、本地 Chroma、本地文件夹都是 MVP 可选的本地方案；用户量、并发、数据价值或合规要求提高后，再按技术适配声明升级基础设施。

| 能力 | 本地开发 / MVP | 正式生产环境 |
| --- | --- | --- |
| 结构化数据 | SQLite 或带 schema 版本的结构化文件 | 托管 PostgreSQL（或平台提供的数据库 / 数据网关）；数据层集中在 repository，本地与线上两种实现跑同一套接口测试 |
| 向量检索 | 本地 Chroma | pgvector 或指定的向量服务 |
| 文件存储 | 本地目录 | 对象存储 |
| 后台任务 | 后端执行并持久化状态 | 满足任务队列触发条件后，用任务队列或公司任务平台 |
| 登录 | 基础登录或暂不实现（业务记录仍带归属字段） | 邀请码换 HttpOnly Cookie 会话（默认）、OAuth、企业 SSO 或统一身份系统 |
| 部署 | 本地运行 | 云托管容器服务（Docker 镜像）、云服务器或公司容器平台 |
| 监控 | 本地日志 | 集中日志、错误告警和性能监控 |

从 MVP 升级到生产前，先输出迁移方案：数据迁移、配置变化、兼容风险和回滚方式，再改代码。

上线前的最低检查（不能只把"网址能打开"当成上线完成）：
- 用户只能看到自己的数据，权限判断在后端；
- 服务重启后数据还在；
- 密钥不在代码、仓库、前端产物和镜像里，线上用平台 Secret 或环境变量注入；
- 会产生费用的云资源都已经告知费用并得到确认。

本插件不包含具体云平台的部署步骤。在 idea-to-launch-kit 工作区里，部署按工具包的《上线部署手册》（腾讯云开发 CloudBase）执行。
